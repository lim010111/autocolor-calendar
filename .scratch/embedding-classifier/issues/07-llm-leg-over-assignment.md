## What to build

Stage 2(LLM)가 **희소한 카테고리 집합에서 과잉 배정**한다. 라이브 prod
계측(2026-07-28, 실사용자 1명, `llm_calls` 184행)에서 hit 56건 중 **52건이
단일 카테고리 "개발"** 로 몰렸고, 사용자가 오분류로 확인한 4건이 전부 이
경로에서 나왔다. 임계값(Stage 1)이 아니라 **LLM leg 의 판단 정책**이
원인이다.

### 계측 근거 (전부 prod 실측, 추정 아님)

**① 오분류 4건은 전부 Stage 2 히트다.** 사용자가 지목한 오분류를
`llm_calls.prompt_summary` 로 역추적한 결과 4건 모두 LLM 호출 기록이
있었다 — Stage 1 임베딩 히트가 아니다. "유사도 임계값이 낮은 것 아니냐"는
초기 가설은 **데이터로 반증됨**.

| 이벤트 제목 | LLM 판정 | 사용자 정답 |
|---|---|---|
| 유플러스 요굼제 가입하기 | 개발 | (해당 없음) |
| 책 읽기(커리어 스킬) | 개발 | 독서 |
| 에스알포스트 지원 | 개발 | 취준 |
| 내면소통 명상 수업 | 운동 | 독서 (운동은 그나마 근접) |

**② 배정이 한 카테고리로 쏠린다.**

```
outcome:  miss 128 / hit 56
hit 분포: "개발" 52 / "운동" 4
```

**③ 같은 입력에 정반대 판정 — 비결정성.** "유플러스 요굼제 가입하기" 는
11초 간격 두 호출에서 **prompt_summary 가 바이트 단위로 동일**한데 결과가
갈렸다:

```
@2026-07-28T06:25:34.461Z  hit  -> 개발    available=["개발","운동"]
@2026-07-28T06:25:45.037Z  miss -> (none)  available=["개발","운동"]
```

같은 사용자·같은 이벤트·같은 카테고리 집합·같은 프롬프트. 임계값이나
카테고리 구성으로 설명되지 않으며, **tie-breaker (f) "genuine ambiguity →
none" 이 안정적으로 발화하지 않는다**는 뜻이다.

**④ 씨앗이 최소 구성이었다.** 계측 시점 사용자 규칙은 이름만 있고 키워드는
`[name]` 폴백, examples 는 비어 있었다 (`#04` 의 keyword-optional 폴백 +
`#05` 의 consent 미구현으로 examples 는 구조적 0):

```json
{"categories":[{"name":"개발","keywords":["개발"],"examples":[]},
               {"name":"운동","keywords":["운동"],"examples":[]}],
 "event":{"summary":"유플러스 요굼제 가입하기","description":"","location":""}}
```

즉 **런칭 직후 신규 사용자가 정확히 겪게 될 상태**다. 씨앗을 늘리면 나아질
수는 있으나, "규칙 2개짜리 신규 사용자에게 오분류가 쏟아진다"는 것은 그
자체로 온보딩 결함이다.

### 이게 왜 §5.3 정책 위반인가

`src/AGENTS.md` "LLM semantic matching policy (§5.3)" 는 anti-overstretch 를
명시한다 — 토큰 겹침만 있는 도메인 불일치와 은유적/희망적 매칭은 거부.
"유플러스 요금제 가입" → "개발" 은 도메인 불일치이고, tie-breaker (f) 대로면
`none` 이 나와야 한다. 프롬프트에 규칙은 있으나 **실제로 지켜지지 않는다.**

### 조사·수정 방향 (구현 세션 재량, 아래는 출발점)

- **먼저 재현**: `evals/` 에 "희소 카테고리 + 무관 이벤트" 케이스를 추가해
  현행 프롬프트의 none-율을 계측. 위 4건 + 비결정성 케이스를
  `user-report-*` 로 넣어 회귀 가드에 편입 (§5.3 의 eval-gate 규칙상
  프롬프트 수정은 eval 통과가 전제).
- **비결정성 축소 — 원인 확인됨**: `callOpenAi` 의 페이로드
  (`llmClassifier.ts:383-392`) 는 `model` / `messages` /
  `max_completion_tokens` / `response_format` 만 보낸다. **`temperature` 도
  `seed` 도 지정하지 않아 모델 기본 샘플링으로 동작한다** — ③ 의 직접
  원인이다.

  ⚠️ 다만 "temperature: 0 을 넣으면 끝" 이라고 단정하지 말 것. 이 프로젝트의
  모델은 gpt-5 계열 nano 이고, 해당 계열은 샘플링 파라미터 지원이 제한적인
  전례가 있다(예: `reasoning_effort=minimal` 이 `gpt-5.4-nano` 에서 거부됨,
  PR-β 2026-05-13). **구현 세션은 먼저 이 모델이 `temperature` / `seed` 를
  실제로 받아주는지 1회 호출로 실측**하고, 거부되면 프롬프트 쪽
  (none 편향 강화)으로 방향을 돌려야 한다. 결정성 확보가 불가능한 모델이면
  "동일 입력 일치율" AC 는 목표치를 재설정할 것.
- **none 편향 강화**: 카테고리 수가 적을 때 `none` 을 더 적극적으로 내도록
  프롬프트 보강. 단 §5.3 의 eval-gate 3종(회귀 ≥90% + 4언어 델타 ≥ -1%p +
  Pattern B grep)을 통과해야 하며, **prompt v7 신규 파일**로 만들고 기존
  버전은 삭제 금지(롤백 경로).
- **대안 검토**: 임계 대신 "카테고리 수 < N 이면 LLM leg 를 아예 건너뛴다"
  같은 게이트도 후보. 과잉 배정보다 미배정이 낫다는 판단이 서면.

**Q1 — 파라미터 수용 여부: 6개 구성 전부 ACCEPT (HTTP 200).**

| 구성 | 결과 |
|---|---|

`reasoning_effort=minimal` 거부 전례(PR-β)는 **일반화되지 않았다**.
`gpt-5.4-nano` 는 샘플링 파라미터를 거부하지 않는다.

**Q2/Q3 — 그런데 파라미터를 넣어도 비결정성이 사라지지 않는다.**
동일 입력 10회 반복, 카테고리 `["개발","운동"]` 고정:

| 제목 | baseline | `temperature: 0` | `temp0 + seed` |
|---|---|---|---|
| 유플러스 요굼제 가입하기 | 10/10 none | 10/10 none | 10/10 none |
| **책 읽기(커리어 스킬)** | **8/10** 개발:8 none:2 | **6/10** 개발:6 none:4 | **6/10** none:6 개발:4 |
| 에스알포스트 지원 | 10/10 개발 | 10/10 개발 | 10/10 개발 |
| 내면소통 명상 수업 | 8/10 운동:8 none:2 | 8/10 운동:8 none:2 | 10/10 운동 |
| **평균 일치율** | **90%** | **85%** | **90%** |

**결론 — "`temperature: 0` 넣으면 끝" 은 실측으로 반증됐다.** 수용은 되지만
일치율이 **개선되지 않고 오히려 나빠진다**(90% → 85%). 파라미터가 조용히
무시되고 있을 가능성이 높다(gpt-5 계열 추론 모델의 알려진 거동). ③ 의 원인은
**샘플링 설정 누락이 아니라 모델 자체의 추론 비결정성**이며, `temperature` /
`seed` 로는 닫히지 않는다.

**따라서 방향은 프롬프트 쪽으로 확정된다** — 이슈 본문이 예비로 적어둔
"거부되면 프롬프트(none 편향 강화)로 전환" 이 이제 유일한 경로다.
`callOpenAi` 에 `temperature`/`seed` 를 추가하는 변경은 **하지 말 것**:
효과가 없고 페이로드만 늘린다.

**부수 관찰 (③ 의 성격을 좁힌다).** 흔들리는 두 건은 정답 카테고리가 목록에
**없는** 경우(책 읽기→독서 없음, 내면소통→독서 없음)이고, 정답이 목록에 있는
"에스알포스트 지원"(→개발)과 명백히 무관한 "유플러스 요금제"(→none)는 10/10
로 안정적이다. 즉 비결정성은 무작위가 아니라 **"애매한 경계에서 none 과 최근접
카테고리 사이를 오간다"** — 타이브레이커 (f) 가 흔들리는 지점이 정확히
관측됐다. 프롬프트의 none 편향 강화가 겨냥해야 할 표면이 이것이다.

**`OPENAI_API_KEY` 블로커는 존재하지 않았다** (위 Blocked by 참조).
